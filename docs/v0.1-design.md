# v0.1 の設計

Phase 0 (`docs/phase0-poc.md`) の結果をもとに決めた、v0.1 の作りです。上限の値は、実機の確認で変えることがあります。

## 範囲

- Claude Code 2.1.332 の mod。`SendUserFile` の結果に付く、画像の添付を描く。
- 確かめる環境は macOS の iTerm2 直下と、iTerm2 の中の Herdr。
- 形式は PNG と JPEG。

## Phase 0 の後に決めたこと

| 項目 | 決め | 根拠 |
| --- | --- | --- |
| 並べ方 | 添付ごとに本体の行を描かせ、画像の添付の直後に画像を置く。添付ごとに「●」の行が付くのは受け入れる | 実機で確かめた (2026-11-27)。本体の行は中身を読めないので、行の中に差し込むことはできない。利用者が決めた |
| 描けない端末 | 画像を足さず、本体の行だけに戻す | brief の F07、AC09 |
| Herdr の判定 | 環境変数 `HERDR_ENV` の有無 (`$.env.get`) | mod から読めることを確かめた |
| FORCE | mod からは立てない。Herdr の中では、利用者が zsh の設定に 1 行を足す | `$.env.set` は成功するが、session の途中でも起動時の `session.start` でも、描画の判定は変わらなかった |
| セルの縦横比 | 初期値 0.41。plugin の設定で 0.2 から 1.0 | brief の「初期値は実機で決める」。最初の実機で測った値 |
| 寸法の読めない JPEG | 描かない | 推測で縮小・拡大しない |

## 処理の流れ

1. `tool.call`: `SendUserFile` の呼び出しが成功したら (`next(e)` の後)、その `tool_use_id` と添付の path を session の state に登録する。
2. `ui.render` の `ToolResult`: 登録のある行だけを扱う。terminal の surface で、画像を描ける端末のときだけ、添付ごとに本体の行を描かせ、画像の添付の直後に `Image` を置く。それ以外は `next(e)` をそのまま返す。
3. 画像の準備は描画の hook の外で行う。済んだら state を書き、その行を描き直す。準備中は本体の行だけを描く。
   - `stat` で実体を確かめる (通常 file、空でない、上限以下)。読むのは、link を解決した path。
   - file を 1 回読み、読む前と後の `stat` (解決した path、大きさ、更新時刻) が同じときだけ、読んだ byte を使う。違えば描かない。
   - 読んだ byte の先頭で形式を確かめ、寸法を読み、上限を当てる。
   - 2 MiB 以下の PNG は、そのまま `Image` に渡す。
   - JPEG と、それを超える PNG は変換する。`mktemp -d` の私的な folder に、確かめた byte の写しを書き (`base64 -D`)、その写しを macOS の `sips` で PNG にする。元の file は変換の道具に渡さない。長辺が 1600 px を超えるときだけ縮める。
   - 変換の後は folder を消す。消せなかったときは、その旨を結果に残す。
   - この処理は `src/artifact/prepare.ts` にあり、読み書きと command の実行は外から渡す (Claude Code とのつなぎでは `$.fs` と `$.process`)。
4. 描けるかの判定: 画面に載った最初の `Image` に、`$.ui.blit` で同じ画像を 1 回送る。`{ deny }` なら、その session では画像を足さず、本体の行だけに戻す。画面に載っているか (`onScreen`) が分からない描画では判定しない。
5. Herdr の中 (`HERDR_ENV` がある) で FORCE が無く、描けないと分かったときは、設定の要ることを 1 度だけ知らせる。

## 上限 (初期値)

値は `src/artifact/limits.ts` にまとめてある。

| 項目 | 値 | 超えたとき |
| --- | --- | --- |
| 元の file の大きさ | 20 MiB | 画像を足さない |
| 画素数 (幅 × 高さ) | 40,000,000 | 画像を足さない |
| 1 辺の長さ | 20,000 px | 画像を足さない |
| 1 つの結果で画像を足す添付の数 | 8 | 9 件目からは本体の行だけ |
| `Image` に渡す PNG | 2 MiB | 長辺 1600 px に縮める。それでも超えたら足さない |
| 表示の幅 | 100 桁、かつ画像が埋める整数の桁数 (1 桁 = 7 px) まで | 縦横比を保って縮める。拡大はしない。1 桁より細い画像だけは 1 桁で描く |
| 表示の高さ | 24 行 | 縦横比を保って縮める |
| cache | 32 枚、合計 64 MiB | 古いものから捨てる。session の memory の中だけで、file には書かない |

## 読み取りの条件

`docs/phase0-poc.md` の 5 節のとおり。読むのは、error でない `SendUserFile` の結果の添付のうち、`isImage` と `pathValidated` が true で、絶対 path で、`media_type` が PNG か JPEG のものだけ。そのうえで、1 で登録した呼び出しのものに限る。

## しないこと (v0.1)

- `SendUserFile` 以外の結果 (`SendUserMessage`、`Read` など)、返信の文の中の path、URL。
- PNG と JPEG 以外の形式。
- resume で再生された古い行への描画。
- terminal 以外の surface (desktop、mobile など)。
- mod から FORCE を立てること。
