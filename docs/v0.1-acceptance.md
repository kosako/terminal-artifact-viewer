# v0.1 の受け入れの確認

brief の受け入れ基準 (AC01 から AC10) を、v0.1 の mod で確かめた結果です。

- 確かめた日: 2026-11-27
- 版: macOS 26.7.3、iTerm2 3.7.9、Herdr 0.9.5 (iTerm2 の中)、Claude Code 2.1.332
- 実機の確認は利用者が行い、結果は画面写しと報告による (PR #16 の記録)。mod は PR #16 の branch を `claude --plugin-dir` で読み込んだ。
- 画像は、発端の出力に似せた 4 枚 (PNG 2 枚、JPEG 1 枚、空白と日本語を含む名前の PNG 1 枚) を、1 回の `SendUserFile` で送った。長い一時 folder の path の下に置いた。

区分は、実機 (利用者が画面で確かめた)、test (`claude plugin test` か node の test で確かめた)、設計 (作りで決めていて、実機でも test でも確かめていない)、未確認。

| AC | 区分 | 結果 |
| --- | --- | --- |
| AC01 実在する PNG の `[image]` | 実機 | Herdr (FORCE あり) と iTerm2 直下で、各行の直後に画像が出た。command や prompt は足していない |
| AC02 JPEG | 実機 | PNG と同じく出た (変換して表示) |
| AC03 4 枚の連続の出力 | 実機 | 4 枚が送った順に、それぞれの行の直後に出た |
| AC04 長い path、空白と日本語を含む path | 実機 | 長い一時 folder の path と、空白と日本語を含む名前の画像が出た |
| AC05 消えた、読めない、壊れた画像 | test | 送った後に消えた file と上書きされた file は、行を残して理由を 1 行出す。壊れた中身や読めない中身は、例外を出さずに断る (node の test)。実機では未確認 |
| AC06 大きな画像、狭い pane、上限を超える入力 | 実機と test | 約 9MB の PNG は縮めて普通の大きさで出た。pane の幅を変えても崩れなかった。上限を超える file、画素数、辺の長さは断る (test) |
| AC07 画像でない file、URL、許可外の path、link 経由 | 実機と設計 | 画像でない file (README) は行だけになった (実機)。読むのは `SendUserFile` が送った添付だけで、返信の文の中の path や URL は読まない。`SendUserFile` は Claude Code の読み取りの権限の rule を当ててから送る。読むのは link を解決した path で、送った時点の実体と違えば読まない (test)。許可外の path を送らせる実機の確認はしていない |
| AC08 scroll、再描画、幅の変更、pane の切り替え | 実機 | Herdr で、scroll、幅の変更、pane の切り替えをして、問題は無かった |
| AC09 未対応の端末、描画の失敗、mod を止めたとき | 実機と設計 | Herdr で FORCE なしのとき、元の表示に戻り、設定の要ることを 1 度知らせた (実機)。mod を止めたときは Claude Code の元の表示になる (mod を読み込まない session と同じ。Phase 0 で確認) |
| AC10 通常の操作と権限の承認 | 設計 | mod は権限の判断に関わる hook を持たない。`tool.call` の hook は `SendUserFile` の実行の後に結果をそのまま返す。実機の承認の流れは、確認の間に変わったところは無かったが、意図して確かめてはいない |

## そのほかに確かめたこと

- resume で開き直した session では、前の session の行は文字だけで出た (実機)。
- 32 枚を超える画像で、行どうしが cache から追い出し合って読み直しが続かないこと (test)。
- 一度描けると分かった端末で、後の行の確認が断られても、画像を止めないこと (test)。

## 未確認のこと

- 確認の後に短くした、Herdr の知らせの文の見え方。
- 32 枚を超える画像を送ったときの実機での振る舞い。
- macOS 以外 (`sips` が無い環境) では動かない。
